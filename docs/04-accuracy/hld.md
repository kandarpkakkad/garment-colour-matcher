# Accuracy — HLD

## Purpose

Know how right the colours are, find out early when they are not, and prove the Kotlin engine
computes what the Python reference computes.

## Two metrics, because they fail independently

- **Angular error** of the illuminant: did the estimator find the light?
- **ΔE2000** of each garment against its true colour under D65: does the person see the right
  colour?

Plus **family errors** — navy read as black, burgundy as brown — counted separately, because
they are what people report as "wrong".

## Three kinds of test data

| | What | Ground truth | State |
|---|---|---|---|
| Synthetic scenes | Generated by `spike/gcm/scenes.py`: a Mondrian background, a figure with skin, hair and garments, rendered under a known light, with noise and 8-bit quantisation | Exact, by construction | Built. Used by the benchmark and the fixtures |
| A public benchmark | Images with a measured illuminant per image (e.g. Cube+), via `bench.py --gt` | The dataset's | Runner built and tested on a generated dataset of the same shape; **not yet run on a real one** |
| The owner's adversarial set | Garments shot with a colour checker in frame; the checker cropped out before the pipeline | The checker | Phase 1 — protocol below; needs the owner's photos |

**Synthetic results prove the mechanism, not the product.** They show that removing garment
pixels defeats the dominant-garment failure *when the rest of the scene behaves like the
generator's*. Real scenes decide whether it does.

## The protocol for the owner's set (from the plan)

- Every test garment shot **with a colour checker in frame**. The checker gives the ground
  truth; cropping it out gives the real no-card input.
- 200+ shots: indoor tungsten, overcast daylight, direct sun, shop fluorescent, mixed window
  and lamp, phone flash.
- Black, white, navy and mid-grey garments, where errors show most.
- The adversarial cases on purpose: one saturated garment over half the frame, in red, then
  blue, then green.

## Gates this owns

| Phase | Gate | How it is checked |
|---|---|---|
| 0 | Median angular error clearly beats gray-world | `bench.py`: synthetic now; a public benchmark next |
| 1 | The dominant-garment case measured, mitigation chosen | `bench.py` on the owner's set |
| 2 | Kotlin reproduces Python within ΔE 0.5 | `FixtureParityTest`, on every engine build |

## Results so far

**Synthetic only.** `tool/spike_in_docker.sh bench`, 2026-11-01: 250 scenes, 128 × 96, six
lights plus mixed, four kinds. Angular error in degrees, median / p90:

| | All | Dominant garment | Neutral garments |
|---|---|---|---|
| Naive gray-world, every pixel | 8.06 / 23.78 | 18.88 / 32.48 | 5.43 / 10.65 |
| Shades-of-gray, garments out | 4.11 / 12.54 | 4.90 / 11.41 | 3.61 / 9.90 |
| **Combined** (the app) | **4.60 / 12.68** | **5.13 / 10.29** | 4.21 / 10.00 |
| Combined without the skin vote | 4.40 / 12.98 | 5.13 / 10.29 | 2.69 / 9.81 |

- **The mitigation works on synthetic scenes.** Removing garments takes the dominant-garment
  case from 18.9° to about 5°. Garment ΔE2000 median 3.18 (combined) against 5.43 (naive);
  family errors 16.4 % against 24.8 %.
- **Mixed light fails, as designed** (D9): about 16° median for the combined estimate.
- **The skin anchor is not settled.** It is biased whenever skin differs from the
  ColorChecker patches it is anchored to, and the synthetic skins (an invented palette) differ
  most at the dark end. Without its vote the median improves and the tail worsens; outfits get
  worse, neutrals better. The evidence points neither way, so the design is unchanged (D6),
  and the benchmark keeps both rows. **Phase 1 decides this with real skin.**
- **Confidence carries information but is not yet calibrated.** `HIGH` scenes had median
  garment ΔE 2.46 against 3.51 for `LOW`, but `HIGH` had the worse p90 (9.77 against 8.72),
  and only 80 of 250 scenes were `HIGH`.
- Shades-of-gray alone has the best median. The combination earns its place through the
  disagreement it measures, not through accuracy, on these scenes.

None of this is evidence about real photos. The phase 0 gate on a public benchmark, and
phase 1, are still to run.

## Non-goals
